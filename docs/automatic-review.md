# 공식 NEW 수집·자동 검수 기준

매일 한국 시간 06:30 수집한다. 등록된 공식 출처의 상품별 NEW 표시를 자동 승인 기준으로 삼는다. 출시일, 30일 이내 여부, 매장별 재고는 승인 조건이 아니다.

- 수집기는 상품별 NEW 배지/공식 NEW 전용 영역을 확인하고 reviewEvidence.explicitNew를 저장한다. 추천 상품, 이미지 날짜, sitemap 수정일만으로 NEW를 추정하지 않는다.
- 명시적인 수집 정책 제한은 계속 준수한다. robots 파일 부재는 허용 확인으로 표시하지 않으며, 이번 변경은 기존 수집기의 정책 검사 범위를 확대하거나 법적 적합성을 보증하지 않는다.
- 자동 승인: 등록 공식 출처 + 유효한 식별자 + 명시적 NEW. 정책 제한/출처 충돌/식별 중복은 예외 처리한다.
- NEW가 사라지면 newStatus=removed, isActive=false로 공개 NEW 목록에서 제외한다. availabilityStatus는 unknown으로 두며 판매 종료라고 단정하지 않는다.
- 수집 실패 시 기존 데이터를 유지한다. 커피는 동일 경로에서 성공한 두 번의 확인에서 누락됐을 때만 NEW 종료 처리한다.
- 관리자 결정은 자동 판정보다 우선하며, NEW 근거가 없는 상품을 공개 NEW 목록에 강제로 추가하지는 않는다.

## 최초 관측 이력

new-history.json에 브랜드별 초기 기준과 과거 상품 식별자를 보존한다. 현재 저장된 목록과 신규 브랜드의 첫 수집은 detectionKind=initial로 표시한다. 이후 기존 브랜드에서 새 식별자가 관측되면 newly_detected로 구분한다. 동일 ID 재등장/이름 변경은 기존 구분과 최초 확인일을 유지한다.

이번 주·이번 달 집계는 newly_detected의 최초 확인일 기준이며 출시일을 뜻하지 않는다. 초기 수집은 별도 표시하고 집계에서 제외한다. NEW가 유지되는 상품은 나이와 무관하게 카테고리 목록에 계속 표시한다.

전환 유예: 2026-10-18까지는 초기 수집도 최초 확인일 기준으로 주/월 집계에 포함한다. 2026-10-19 한국 날짜부터 위 신규 발견 기준으로 전환한다. GitHub Pages는 정적 빌드이므로 실제 화면 전환은 해당 날짜의 첫 성공한 자동 갱신·배포(예정 06:30 이후)에 반영된다.

## 알림

출시일·판매 증명 부족 또는 단순 NEW 미확인은 관리자 알림을 보내지 않는다. 출처/식별/근거 URL 충돌, 수집 실패 등 예외만 알린다. GitHub Actions에서 상품+사유 최초 1회, 한국 날짜별 최대 한 이슈로 묶는다. 당일 추가 및 길이 초과 항목은 다음 날로 이월한다. 로컬 review:notify는 전송 없는 미리보기다.

추가 브랜드별 실패, 커피 브랜드의 전체·일부 경로 실패 및 전체 작업 실패를 보고한다. 커피는 한 브랜드의 예외가 다른 브랜드 수집을 중단하지 않도록 격리하고 coffee-collection-status.json에 결과를 저장한다. 같은 실패가 지속되면 발생 시점을 유지해 알림을 반복하지 않으며, 복구 후 재실패는 새 발생으로 알린다. 실패한 경로는 상품 누락 판정에서 제외한다. 원문 오류 메시지는 상태 파일에 저장하지 않는다. 그 밖의 기존 수집기에서 내부 부분 실패가 경고로만 끝나는 경우는 개별 실패 알림 연결이 추가로 필요하다.
