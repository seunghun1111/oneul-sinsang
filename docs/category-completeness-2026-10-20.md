# CU 카테고리별 완전성 보호

## 범위

CU 7개 공식 카테고리에 우선 연결했다. 판정 헬퍼는 분리했으나 다른 브랜드에 자동 적용하지 않았다. 운영 수집·배포·알림 전송 및 과거 제외 상품 복원은 하지 않았다.

## 수집 완전성

- 카테고리별 성공 페이지 수·실제 요청 수·고유 NEW 건수·완료 여부·허용된 실패 사유를 보고서에 기록한다.
- 중간 페이지에 NEW가 없어도 더보기 신호가 있으면 계속 확인한다. 더보기 없는 정상 상품 목록 또는 명시적 빈 목록에서만 끝에 도달한 것으로 취급한다.
- 반복 페이지, 중복/누락된 상품 ID, 추출되지 않은 NEW 배지, 빈 HTML, 더보기가 남은 10페이지 상한은 미완료로 처리한다. 상한을 무제한으로 늘리지 않는다.
- timeout/connection/network는 해당 페이지 요청·본문 읽기에 한해 최대 1회 재시도한다. 정책·TLS·HTTP·구조 오류를 반복하거나 우회하지 않는다.
- 한 카테고리 실패가 다른 카테고리의 진단·긍정 관찰을 버리지 않도록 격리한다. 전체 배열만 사용하는 기존 진입점은 미완료를 성공으로 반환하지 않는다.

## 제외 보류

- 기존 활성 상품이 있는 카테고리가 0건이면 보류한다.
- 기존 활성 상품 10개 이상인 카테고리가 이전 활성 건수의 50% 미만이면 급감으로 보류한다. 초기 보수적 휴리스틱이며 진짜 종료인지 확정하지 않는다.
- 수집 미완료 카테고리도 보류한다. 미등록 분류의 기존 상품도 검증 완료 분류에 없으면 누락 판정을 하지 않는다.
- 보류 카테고리의 미관찰 상품은 상태·누락 횟수·긍정 확인 시각을 보존한다. 정상적으로 추출된 개별 NEW의 추가·갱신과 다른 검증 완료 카테고리의 2일 누락 판정은 계속한다.
- 전체 0건 보호는 기존대로 우선 적용한다. 과거 제외 상품은 긍정 재관찰 없이 복원하지 않는다.

## 알림

- 카테고리 문제가 있으면 브랜드 보고서를 확인 필요로 기록하고 `categoryIssues`를 남긴다. 전체가 정상이라고 표시하지 않는다.
- 기존 일일 알림 경로에서 문제 카테고리만 사유별로 알린다. 정상 카테고리나 상품별 승인 요청은 추가하지 않는다.
- 같은 카테고리·사유가 지속되면 최초 발생 시각을 유지해 중복 키를 억제한다. 회복 후 재발은 새 발생으로 구분한다. 같은 날 1개 digest 제한은 유지한다.
- 운영 화면의 카테고리 상세 UI 추가는 포함하지 않았다. 보고서 및 기존 일일 알림에서 우선 확인한다.

## 검증·한계

- 네트워크 없는 fixture로 정상 종료, NEW 없는 중간 페이지, 반복·상한, HTTP 실패, 구조 실패, 빈 HTML, 0건·급감, 미완료 상품 보존, 알림 키 안정성, 페이지 재시도 검증.
- 실제 사이트의 페이지 버튼 구조와 운영 결과는 배포 후 승인된 수집에서 추가 확인해야 한다. 완전성 신호를 인식하지 못하면 안전하게 보류하는 방향이다.
- 급감하지 않는 일부 누락까지 완벽히 탐지하지 못한다. 2회 누락 보호와 함께 사용한다.
- 상품 데이터 변경 없음. 품질 총 1236 / 공개 911 / 오류 0 / 기존 보완 34.
