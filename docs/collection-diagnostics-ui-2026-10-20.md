# 통합검수함 수집 진단 표시

## 구현

- 브랜드별 상세 펼치기에 실제 수집 시도·재시도 횟수, 최초 오류 코드, 최종 실패 단계 및 HTTP 상태를 표시한다.
- CU 상세에 이번 수집 NEW 후보 수, 페이지 완료 여부·페이지 수·요청 수, 카테고리별 제외 보류 사유를 표시한다. 후보 수를 공개 상품·재고 수량으로 오해하지 않도록 안내한다.
- 마지막 전체 정상 확인과 최근 실패 확인 시각을 별도 표시한다. 실패 이후 복구해도 두 시각을 각각 보존한다. 미래/잘못된 시각은 신규 이력으로 채택하지 않는다.
- 카테고리 보류가 있으면 일반 수집 실패 문구 대신 정상 NEW 반영·미관찰 상품 유지의 차이를 설명한다.
- 이전 보고서에는 진단 정보가 없을 수 있다. 시도 0회/HTTP 0/성공으로 추정하지 않고 기록 없음과 다음 수집 이후 제공 안내를 표시한다.

## 전달 경로 및 안전성

수집 상태 보고서 → 공통 `buildCollectionHealth` → GitHub `collection-health.json` → Site 조회 경계 → 통합검수함 패널.

- 생성 경계와 원격 조회 경계에서 동일 정규화를 적용한다. 허용된 오류 코드·단계·HTTP 100~599 정수·카테고리명·건수·페이지 수만 전달한다.
- 원문 예외·응답·임의 필드·URL·토큰은 새 진단 필드에 포함하지 않는다.
- 조회·필터·상세 표시만 변경했다. 승인/수집 실행/인증·인가/배포 audience는 변경하지 않았다.
- 공통 데이터 생성 코드는 GitHub 측 배포가 필요하고, 패널은 ChatGPT Site 별도 배포가 필요하다. Site만 배포해도 기존 JSON에 없는 값을 소급 생성할 수 없다.
- 운영 데이터·보고서의 확인 시각을 이번 로컬 작업으로 갱신하지 않았다.

## 검증

- 루트 테스트 225개 통과. 잘못된·민감 필드 제거, 기존 형식 호환, 정상/실패 시각 보존 포함.
- Site 타입 검사 및 Vinext 클라이언트/RSC/SSR 빌드 통과.
- UI 렌더 검증 통과: 정상·실패·기록 없음·로딩·오류·카테고리 사유·표 접근성.
- 운영 API·DB에 접근하지 않는 전용 loopback fixture에서 실제 React 패널의 펼치기·확인 필요 필터·브랜드 검색을 브라우저로 검증했다. 가상 데이터임을 화면에 표시한다.
- 스크린샷 `collection-diagnostics-ui-2026-10-20.png`. 운영 전체 페이지·실기기 모바일 검증은 하지 않았다. 기존 가로 스크롤 표 구조를 유지한다.
- Sites 스킬의 로컬 미리보기·검증 흐름을 사용했다. 운영 배포·수집·알림 전송 및 원격 소스 동기화는 하지 않았다.
