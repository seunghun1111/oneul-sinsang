# 공통 공개 수집 HTTP 전송

`scripts/lib/collection-http.ts`의 `collectionFetch`를 GitHub 일일 수집 파이프라인의 기본 전송 함수로 사용한다. CU, 세븐일레븐·이마트24, 카페, 외식 9개 브랜드, 배스킨라빈스, 추가 치킨·아이스크림, 식품 5개 브랜드 발표, 개별 발표 재확인, 카페 이미지 보완에 연결했다. ChatGPT Site 자체의 별도 수집 API 코드를 변경한 것은 아니다.

## 공통 조건

- HTTPS만 허용하고 자격증명이 포함된 URL, 제한 도메인, IP 직접 주소, localhost/local/internal 호스트, 비표준 포트를 배제한다.
- 인증·쿠키·프록시 인증 헤더를 차단하고 credentials를 omit으로 설정한다.
- 리다이렉트는 manual로 고정한다. 301/302 응답은 기존 수집기의 HTTP 오류 처리로 전달되며 다른 도메인을 자동 방문하지 않는다.
- 요청마다 최대 20초 제한과 호출자가 지정한 취소 신호 중 먼저 발생하는 조건을 적용한다.
- 원래 POST 본문과 콘텐츠 유형, 공식 요청에 필요한 Referer는 유지한다.
- 전송 오류의 원문은 재노출하지 않는다.

호스트가 허용되는 것은 해당 사이트의 수집 허가를 의미하지 않는다. DNS 응답 주소를 검증하거나 고정하는 기능까지 구현한 것은 아니다.

## 공통 robots 확인 — 후속 구현

기본 `collectionFetch`는 안전한 전송 계층 위에 robots 확인을 추가한다. 상품 URL 요청 전에 같은 origin의 `/robots.txt`를 GET으로 확인한다. 정책 요청에는 상품 POST 본문·Referer·인증정보를 전달하지 않는다. 명시적인 robots 요청 자체는 재귀 검사하지 않는다.

정상 정책은 origin·사용자 에이전트별 1시간 동안 캐시하고 병렬 요청은 같은 Promise를 공유한다. 실패는 재시도 폭주를 막도록 1분 캐시한다. 404·410만 정책 미제공으로 간주한다. 다른 HTTP 실패, 리다이렉트, 비정상 콘텐츠 유형·HTML 본문, 512KB 초과는 상품 요청을 중단한다. 정책 미제공은 수집에 대한 법적 허가를 뜻하지 않는다.

공통 `robots-policy.ts`는 구체적인 사용자 에이전트, 와일드카드, 쿼리, 경로 끝 표시, 가장 구체적인 규칙 및 동일 길이 Allow 우선순위를 적용한다. 기존 카페·추가 브랜드용 함수도 같은 해석기를 다시 내보내며 브랜드별 NEW 판별은 바꾸지 않는다.

정책 차단·오류는 수집 실패로 전달해 기존 데이터 보존 흐름을 유지한다. 이를 정상 NEW 0건으로 기록하지 않는다. 브랜드에 더 엄격한 기존 정책 검증이 있으면 그대로 적용한다. ChatGPT Site의 별도 수집 API에는 이 루트 전송 계층을 적용하지 않았다.

회귀 테스트 131개·타입 검사 및 허용된 스타벅스 공식 메뉴의 정책 확인 후 HTTP 200 응답을 검증했다. 아직 운영 배포 전이다.

## 검증 및 운영

제한 URL은 실제 네트워크 요청 없이 거부되는지, 리다이렉트를 따라가지 않는지, POST 본문과 취소 신호가 유지되는지, 인증정보와 원문 오류가 노출되지 않는지 회귀 테스트로 확인한다. 기존 수집 실패 시 데이터 보존·NEW 판별 테스트도 함께 실행한다.

배포 후 새로 실패하는 브랜드가 있다면 먼저 공식 HTTPS 주소나 리다이렉트 변경을 확인한다. 인증 차단·리다이렉트 제한을 우회하여 복구하지 않는다. 현재 변경은 로컬 구현 상태이며 운영 배포 전이다.
