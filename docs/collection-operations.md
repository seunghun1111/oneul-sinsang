# 수집 운영 현황

관리자 전용 통합 검수함의 수집 운영 현황은 상품 승인 상태와 별개다. 카페·편의점·외식·아이스크림·추가 브랜드·식품 발표의 47개 등록 브랜드 경로를 표시한다.

- 매일 수집 뒤 report:collection이 개별 상태 파일을 collection-health.json으로 집계한다. 이전 집계에서 실제 마지막 전체 성공 시각을 보존한다.
- 마지막 정상 확인은 status=success의 확인 시각만 사용한다. 최초 발견일이나 상품 판매 확인일을 성공 이력으로 추정하지 않는다. 부분 성공은 완전 정상 확인을 갱신하지 않는다.
- 기록이 없거나 확인 시각이 잘못됐으면 ‘기록 없음’, 36시간 넘게 지난 결과는 ‘갱신 지연’으로 구분한다. 갱신 지연은 수집 실패로 확정하지 않는다.
- 갑작스러운 0건은 기존 NEW 유지 및 관리자 확인 필요 사유로 표시한다. 원문 오류·토큰·임의 출처 URL은 집계에 포함하지 않는다.
- 그룹·브랜드 검색 및 확인 필요 필터를 제공한다. NEW 후보 수는 수집기가 반환한 후보 수이며, 이번 주 신규 발견 수나 승인 상품 수가 아니다.
- /api/collection-health는 기존 검수 API와 같은 ChatGPT 로그인 확인을 사용한다. 운영 기록 조회가 실패하거나 늦어져도 상품 검수 조회는 독립적으로 진행한다.
- 정적 JSON 기록은 운영 도중 실시간 로그가 아니다. 전체 수집 작업이 커밋 전에 실패하면 새 집계가 운영에 게시되지 않을 수 있다. 최근 확인 시각을 보고 Actions 실행 기록을 별도로 확인해야 한다.

운영 배포 시 GitHub 데이터 파일을 먼저 반영한 다음 Sites 화면을 게시한다. 순서가 바뀌거나 파일 조회가 실패하면 운영 현황만 오류 안내가 나오고 상품 검수는 유지된다. 새 알림 채널·접근 권한·수집 기준은 변경하지 않는다.
