# 잔여 9개 브랜드 후속 점검

이전 지연·재시도·더벤티 변경은 보존했다. 이번에는 기존 실패 원인을 더 구체화하고 공식 대체 경로의 안전한 사용 가능성을 확인했다. 운영 배포·재수집·상품 상태 갱신은 하지 않았다.

| 브랜드 | 후속 확인 | 결론 |
| --- | --- | --- |
| 롯데리아·엔제리너스 | 기존 공식 롯데이츠 메뉴 robots 명시 제한 지속 | 해당 경로 보류. 우회 없음 |
| 맘스터치 | www robots가 302로 apex 홈페이지에 이동. 공식 이동 목적지 apex도 robots 미확인 | 일반 홈페이지 이동을 robots 허용으로 처리하지 않음 |
| 아티제 | robots HTTP 200이지만 Content-Type text/html, 홈페이지 응답 | HTTP 200만으로 정책 정상 처리하지 않음 |
| 투썸플레이스 | 등록 메뉴 호스트 DNS 실패. 공식 www robots는 HTTP 403 | 검색 포털의 캐시·다른 호스트의 페이지를 검증된 대체 수집원으로 간주하지 않음 |
| 파스쿠찌·탐앤탐스 | 등록 공식 호스트 TLS 실패 지속 | 인증서 검증을 끄거나 HTTP로 낮추지 않음 |
| 할리스 | 공식 MD는 접근되지만 개별 NEW 근거 추출 0, 스토어는 정책 제한 | 파일명 날짜나 단순 목록을 NEW 근거로 사용하지 않음 |
| 커피베이 | 공식 메뉴·동일 출처 정적 코드 확인. 개별 상품 NEW를 안정적으로 연결할 공개 데이터 구조 미검증 | 임의 API·로그인·폼 요청으로 확장하지 않고 구조 보류 유지 |

## 코드 보완

- `policy-diagnosis.ts`: 정책 응답의 홈페이지 이동·정책 이동·거절·잘못된 응답 형식·미제공·본문 검증 필요를 분리한다. 허용 판단이나 이동 수행은 하지 않는다.
- 진단기는 `policy_unavailable`일 때 robots 헤더만 추가 확인하고 응답 본문은 취소한다. HTML·키·원문 오류·이동 URL은 저장하지 않는다.
- 동일 origin은 Promise 캐시로 중복 robots 진단을 방지한다. 아티제 4개 경로가 같은 오류를 내더라도 추가 진단 요청은 한 번만 수행한다.
- 실제 진단 결과는 `collection-attention-current.json`에 반영했다. 상품 데이터·collection-health·검수·알림 상태를 성공으로 갱신하지 않는다.

## 검증과 남은 한계

- 전체 테스트 207개 통과, lint 오류 없음 (기존 img 경고 2개), 정적 빌드 870페이지 성공.
- 정책 진단 테스트는 홈페이지 이동·누락된 Location·403·HTML·404·정책 본문 미검증 구분 및 민감 URL 미저장을 포함한다.
- 운영에서는 여전히 확인 필요 12곳이다. 앞선 로컬 진단상 세븐일레븐 13개, 더벤티 25개·이미지 25개, 컴포즈 메뉴 접근을 확인했으나 운영 반영하지 않았다.
- 잔여 9곳의 복구는 완료되지 않았다. 외부 정책·DNS·TLS 개선 또는 개별 NEW 근거가 있는 허용된 공식 경로 검증이 필요하다.
- 현재 로컬 변경을 배포할 수 있지만, 배포만으로 이 9곳이 정상화된다고 보장할 수 없다.
