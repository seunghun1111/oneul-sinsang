# 전체 브랜드 수집 진입 경로 재점검

2026-10-17 한국 시간 기준. 47개 브랜드의 설정과 수집기 첫 요청에서 진입 경로를 발견해 정책부터 확인했다. 상품 상세·페이지네이션·동적 API 전부나 NEW 판별을 검증한 결과는 아니다. 기존 상품·검수·알림 데이터는 수정하지 않았다.

## 결과

초기 65개 경로를 확인하고 컴포즈의 잘못된 MD 1개를 수집 대상에서 제외한 후 64개를 재검사했다.

| 결과 | 경로 수 | 의미 |
| --- | ---: | --- |
| reachable | 48 | GET HTTP 성공. 상품 구조·NEW 수집 완료를 뜻하지 않음 |
| policy_hold | 12 | robots 제한/조회·형식·TLS·DNS 오류로 본문 요청 보류 |
| collector_method_required | 3 | CU·세븐일레븐·버거킹 POST 진입점. GET 진단으로 성공/실패 판정하지 않음 |
| http_error | 1 | 커피베이 403. 우회하지 않음 |

정책 상태 자체는 허용 45·미제공 7·명시적 제한 3·확인 실패 9경로다. robots 미제공은 사이트의 포괄적 허락을 의미하지 않는다. 상세 주소·확인 시각은 src/data/collection-policy-status.json 및 collection-route-status.json 참고.

## 수정

- 커피빈: 매개변수 없는 메뉴의 302 Location을 원래 URL 기준으로 해석했다. 같은 origin의 /menu/list.asp?category=13을 별도 정책 검사 후 요청했고 200, 에스프레소 음료 제목을 확인했다. 이 경로로 교체하고 에스프레소만 포함함을 명시했다. 다른 메뉴 전체를 확보했다고 표시하지 않는다.
- 컴포즈: /menu/category/98609는 재확인에서도 404. 공식 대체 MD 경로를 찾지 못해 이 경로를 자동 수집과 공개 링크에서 제외했다. 기존 상품은 유지하며 MD 전체를 지원한다는 안내를 제거했다.
- 공통 진단: 기존 수집기의 요청 메서드를 정책 보고서에 보존한다. POST 전용 경로에 GET을 보내서 오류로 오인하던 진단 문제를 수정했다. 요청 본문·인증 정보는 수집하거나 저장하지 않는다.
- check:routes 명령을 추가했다. 1시간 이내의 정책 보고서가 필요하며, 허용/미제공 경로에만 robots 재검사 후 GET을 요청한다. 리다이렉트는 추적하지 않고 origin/path만 기록한다. 수집기·상품 데이터·검수·알림은 실행하지 않는다. 일일 workflow에 자동 추가하지 않았다.

## 유지한 제한

롯데리아·엔제리너스·할리스 네이버 스토어는 명시적 제한으로 유지했다. 맘스터치 정책은 302, 아티제 4경로는 정책 본문 형식 오류다. 매머드·탐앤탐스·파스쿠찌는 실행 환경의 TLS 검증 실패, 투썸 등록 호스트는 DNS 실패다. 검증 우회나 추측한 대체 주소를 적용하지 않았다. HTTP가 정상인 카페도 NEW 구조·MD·동적 목록 미지원은 여전히 남을 수 있다.

테스트·타입 검사·린트로 로컬 검증했다. 변경은 운영 미배포이며 앞서 준비한 피자헛 판매 근거 보완도 별도로 남아 있다.
