# 수집 단계 진단 및 CU 누락 보호

## 변경

- 공통 전송 실패는 robots 요청과 상품 요청을 구분한다. robots의 HTTP·형식·HTML·크기·본문 읽기 오류도 단계와 상태 코드로 구분한다.
- CU·세븐일레븐·일반 커피 상품 응답의 HTTP 오류 및 본문 읽기 실패를 같은 공통 오류 형식으로 기록한다.
- 일반 브랜드 보고서는 `failureDetail`, 커피 보고서는 경로 실패별 `failureDetails`를 보존한다. 기존 실패 코드·재시도 횟수·정책 제한은 유지한다.
- 상세 기록은 허용된 4개 단계 및 100~599 정수 상태 코드만 포함한다. URL·쿼리·응답 원문·헤더·원본 예외는 저장하지 않는다.
- UI 표시 확장은 포함하지 않았다. 다음 운영 수집 보고서에서 상세 필드를 확인할 수 있다. 기존 실패의 원인을 소급 생성하지 않는다.

## CU 보호 규칙

- 정상이고 비어 있지 않은 수집 결과에서 기존 활성 상품이 누락되면 첫 번째에는 유지한다.
- 서로 다른 한국 날짜에 두 번째로 누락되면 NEW 목록에서 제외한다. 같은 날 재실행은 횟수를 늘리지 않는다.
- 재등장하면 누락 횟수를 초기화한다. 전체 0건은 기존 보호 규칙에 따라 상태·횟수 모두 보존한다. 수집 실패 시 병합 자체를 수행하지 않는다.
- 과거 제외 상품은 자동 일괄 복원하지 않는다. 공식 NEW에 다시 관찰된 상품만 기존 병합 규칙에 따라 재등장할 수 있다.
- 최초 발견일·검수 상태·이미지·최근 긍정 확인 시각을 첫 누락 때문에 변경하지 않는다.
- 두 번 반복되는 부분 수집 누락까지 완전히 방지하는 것은 아니다. 카테고리별 완전성·급감 검증은 별도 과제다. 판매 종료 판정은 하지 않는다.

## 검증

- 기존 테스트 및 추가 실패 진단·누락·한국 자정 경계 테스트 수행.
- lint 오류 0, 기존 img 경고 2개. TypeScript 검사 통과.
- 상품 데이터 변경 없음. 품질: 총 1236 / 공개 911 / 오류 0 / 보완 34.
- 운영 재수집·배포·알림 전송 없음. 배포 후 실제 실행으로 세 브랜드 복구 여부를 별도 검증해야 한다.
