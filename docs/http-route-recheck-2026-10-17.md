# HTTP 실패 5개 브랜드 공식 경로 점검

robots 게이트를 통과한 공식 페이지에만 요청했다. 자동 redirect 추적, 쿠키 설정, 인증·TLS 우회는 하지 않았다. 상태 코드는 이 로컬 점검 시점의 결과이며 다른 실행 환경에서 달라질 수 있다.

| 브랜드 | 관측 | 조치 |
| --- | --- | --- |
| 컴포즈커피 | 기존 메뉴·MD 404. 공식 홈 → index1 → 새 메뉴 링크는 200 | 메뉴와 소식 링크 교체. 대체 MD 링크는 발견하지 못해 기존 경로를 재확인 대상으로 명시. 추천메뉴를 NEW로 추정하지 않음 |
| 커피빈코리아 | 메뉴 302, 같은 pathname으로 이동. 쇼핑 경로 200 | 이동 조건·NEW 추출 확인 전 그대로 유지. redirect만으로 자동 허용하지 않음 |
| 커피베이 | 메뉴 403 | 접근 거부를 우회하지 않고 보류 |
| 공차 | 기존 php 메뉴·MD 404. 공식 홈 → /brand → 새 신메뉴 200, 메뉴 목록에서 MD 링크 발견 | 공식 개편 링크로 교체. MD 응답 및 상품별 NEW 판별은 후속 검증 필요 |
| 테라로사 | /shop 404. 공식 홈에서 커피(category=12)·굿즈(category=88) 발견, 두 경로 200 | 커피·MD 분리. 정적 HTML에서 NEW 근거를 찾지 못했으므로 일반 상품을 신규 후보로 생성하지 않음 |

이번 변경은 출처 설정의 경로 수리이며 신규 상품 수집 복구 완료가 아니다. 공차 신메뉴·컴포즈 메뉴도 현재 공통 파서에서 NEW 후보 0건이었다. 성공 HTTP와 NEW 추출 성공은 구분해야 한다. 기존 상품·승인 상태·정책 점검 JSON은 소급 변경하지 않았다. 새 경로의 화면 정책 배지는 일일 check:policies 실행 전까지 점검 전으로 표시된다.

로컬 구현이며 배포하지 않았다. 상품별 NEW 구조·동적 목록과 남은 MD 경로를 검증한 후 수집 범위를 넓힌다.

## 카드 단위 파서 보완

official-coffee-cards.ts에서 세 브랜드의 동일 상품 링크 안에 명시된 NEW 텍스트/이미지 alt와 상품명을 함께 요구한다. 동일 카드의 안전한 이미지만 연결하고, 한 이름에 서로 다른 이미지가 있으면 기존 공통 이미지 로직처럼 보류한다. 브랜드별 예외는 상세 주소 형식과 이름 위치뿐이다. 기존 일반 파서로 되돌아가 메뉴 아이콘을 상품 근거로 읽지 않는다. script/style/주석·숨김 표시·다른 origin 링크·캠페인 상세 링크는 제외한다.

실제 관측: 컴포즈는 개별 메뉴 카드에 NEW를 찾지 못했고 NEWS/COMMUNITY 메뉴에만 아이콘이 있었다. 공차 신메뉴 페이지는 상품명 없는 캠페인 이미지와 new_menu_detail 링크다. MD 목록의 product_detail 카드는 확인했으나 NEW를 찾지 못했다. 테라로사 정적 응답에서도 NEW 근거를 찾지 못했고 추가 구조 조회 한 번은 시간 초과였다. 따라서 실제 NEW 후보를 양성 검증한 브랜드는 없다. 양성·음성 synthetic fixture로 파서 조건을 검증했으며 CSS로만 숨겨진 배지·앵커 밖 배지·동적 데이터는 별도 검증이 필요하다. 캡처한 원문 전체나 개인정보는 fixture에 저장하지 않았다.

## 정상 0건과 구조 오류 구분

세 브랜드에는 상품 식별 링크 수와 읽은 이름 수를 비교하는 구조 검사를 적용했다. 이름을 하나도 읽지 못하거나 일부 식별 상품의 이름이 누락되면 structure 실패로 기록하고 해당 경로를 verifiedUrls에서 제외한다. 이에 따라 기존 상품 누락·종료 판정에 사용하지 않는다. 모든 식별 카드의 이름을 읽었으나 명시적 NEW가 없는 경우만 정상 0건이다. 캠페인 목록은 상품 카드가 아니므로 정상 수집 성공으로 위장하지 않는다. 실제로 상품이 전혀 없는 정상 빈 페이지도 현재는 보수적으로 구조 확인 대상으로 남는다.
