# 수집 진입경로 정책 사전 점검

`npm run check:policies`는 robots만 읽는 진단 명령이다. 상품 요청·DB 접근·검수 판정·알림 전송은 하지 않는다. 상품 엔드포인트를 요청한 것처럼 가정하는 로컬 probe를 공통 robots 계층에 전달하고, 실제 전송은 `/robots.txt`에 한정한다.

카페·추가 브랜드 경로는 등록된 source 설정을 사용한다. 나머지는 실제 수집 함수에 네트워크를 하지 않는 발견용 fetcher를 전달해 수집 진입 URL을 얻는다. 따라서 모든 상세 URL이나 후속 동적 요청을 검사한 것은 아니다. 스타벅스 원두처럼 설정에는 있지만 아직 별도 수집 미지원인 경로도 포함되므로, 허용 결과를 수집 구현 완료로 해석하면 안 된다.

브랜드·URL 중복을 제거하고 최대 4개 작업을 병렬 실행한다. 같은 origin의 robots 응답은 공통 계층에서 공유한다. 결과는 `src/data/collection-policy-status.json`에 저장한다. 원문 정책·오류·인증정보는 보고서에 저장하지 않는다.

2026-10-17 최초 점검: 47개 브랜드, 64개 진입경로 중 허용 45, 정책 미제공 7, 명시적 차단 2, 확인 실패 10개였다. 확인 실패는 같은 사이트의 여러 경로를 포함한 경로 수이며 브랜드 수가 아니다. 이후 상태는 JSON의 checkedAt과 결과를 확인한다.

명시적 차단은 롯데리아의 lotteeatz 공식 경로와 할리스의 네이버 스토어 경로였다. 공통 정책 적용 배포 후에는 이를 우회하지 않고 새 수집을 중단한다. 실패·차단이 상품 종료나 NEW 해제라는 뜻은 아니다. 기존 데이터는 보존한다. 정책 미제공도 법적 허가를 뜻하지 않는다.

초기 진단은 수동 실행용으로 추가했다. 후속 공개 화면 연동에서는 오래된 결과가 고정되지 않도록 기존 일일 workflow에 정책 점검 단계도 연결했다. 이 단계는 상품을 재수집하지 않고 robots만 다시 확인하며, origin별 요청은 캐시로 합친다. 화면에서는 36시간 이상 지난 결과를 재확인 필요로 표시한다. 정책 확인 시각은 한국 시간으로 안내한다. 현재 robots 공통화·진단 및 화면 연동은 아직 배포 전이다.
