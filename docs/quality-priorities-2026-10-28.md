# 브랜드별 품질 진단과 조치 우선순위

## 구현

품질 검사에 브랜드별 공개 상품 수, 보완 대상 수, 오류·누락 사유별 건수, 가장 오래된 상품 확인 시각, 운영 기록의 유효성, 조치 순서를 추가했다.

- 우선순위: 데이터 오류 → 최근 기록에서 확인된 수집 실패 → 재확인 필요 → 이미지·분류 보완.
- 36시간이 지난 운영 기록은 현재 장애 근거로 사용하지 않는다. 브랜드의 여러 경로 중 오래된 기록이 섞인 경우도 최신 기록 대조를 먼저 안내한다.
- 상품 한 개에 이미지 누락과 재확인 기한 초과가 함께 있어도 보완 상품 수는 한 번만 집계한다. 사유별 건수는 각각 표시한다.
- 비공개 상품은 공개 누락 통계에서 제외한다. 공개 상품이 없어도 최근 수집 실패가 기록된 브랜드는 조치 목록에 포함한다.
- 잘못된 날짜뿐 아니라 미래의 발견·확인·생성·수정 시각도 데이터 오류로 분류한다.
- 기존 보고서 필드를 유지하고 summary를 추가했다. 원본 상품과 운영 상태는 수정하지 않는다.

## 사용

```sh
# 파일을 저장하지 않고 요약 검사
npm run check:quality -- --check

# 브랜드별 사유와 조치 안내까지 출력
npm run check:quality -- --check --details

# docs/catalog-quality-current.json에 로컬 보고서 저장
npm run check:quality
```

--check는 파일을 쓰지 않는다. 구조적 데이터 오류가 있으면 종료 코드 1, 단순 누락·오래된 기록은 안내로 남긴다. 알 수 없는 옵션은 실행 전에 거부한다.
