# 수동 검수 최소화 설계 (정책 2026-10-16-v2)

목표는 승인율을 억지로 높이는 것이 아니라, 확실한 신상품은 자동 승인하고 신상 근거가 없는 상품은 사람이 승인할 필요가 없는 비공개 관찰 대상으로 분리하는 것이다.

| 조건 | 자동 처리 | 사람의 역할 |
| --- | --- | --- |
| 공식 상품별 NEW / 검증된 교촌 code=21 | 공개 승인 | 없음 |
| 허용된 공식 보도자료 경로, 상품명 일치, 검증된 발표일 30일 이내, 최근 36시간 이내 수집 | 출시 발표 근거로 공개 승인 | 없음 |
| 30일 이전 공식 발표이고 현재 NEW 없음 | 비공개 보관 | 없음 |
| 미래 공식 발표일 | 비공개 날짜 대기 | 잘못된 날짜라면 수집기 수정 |
| NEW 없음·검색/판매 링크만 있음 | 비공개 관찰 | 승인 요청하지 않음 |
| 새 실패 수집 결과 | 자동 재시도 | 새 실패가 3회 연속이면 경로 수정 |
| 출처 불일치·중복 식별자·날짜/상품명 근거 오류 | 관리자 확인 필요 | 승인보다 원인 수정 우선 |
| 정책 차단·공식 NEW 종료 | 자동 제외 | 판매 종료라고 단정하지 않음 |
| 기존 관리자 판정 | 그대로 유지 | 명시적 변경 전 덮어쓰지 않음 |

## 구현

- `auto-review.ts`: 승인·비공개 판정과 처리 행동을 분리한다. `decision`은 기존 공개 필터 계약을 유지한다. `action`은 publish/observe/archive/scheduled/retry/manual/exclude다.
- 공식 발표 수집기 5곳(풀무원·오리온·매일유업·삼양식품·빙그레)은 기존 제목·본문 검증 후 실제 상품명·발표일·출처 URL을 구조화해 저장한다. 과거 description, 이미지 수정일, 발견일로 공식 발표 근거를 만들어내지 않는다.
- `review-queue.ts`: 관리자 판정 우선, 새 수집 결과의 확인 시각으로만 재시도 횟수를 올린다. 같은 보고서의 재실행은 새 실패가 아니다. 새 상품 ID 발견으로 집계하지 않는다.
- 일일 수집 후 `review:auto`가 `review-queue.json`을 생성하고 기존 데이터와 함께 반영하도록 연결했다.
- 검수함은 기본적으로 관리자 예외만 보여준다. 관찰·재시도·과거 기록은 자동 처리 구분 필터로 조회한다. 기존 pending 숫자는 수동 승인해야 할 개수가 아니다.
- 알림은 queue의 관리자 예외를 브랜드/사유로 묶는다. 기존 일일 1회 요약·중복 방지를 유지하고 관찰함은 알림하지 않는다. 수집기 장애 알림은 기존대로 유지한다.
- `npm run review:preview`: 네트워크·저장·배포·알림 없는 로컬 시뮬레이션.

## 한계와 적용 절차

- 네이버 자동검색·OCR·AI 추정으로 승인하는 기능은 넣지 않는다. 새 인증정보가 필요하지 않다.
- 관찰 상품은 다음 일일 수집의 새 근거로 다시 평가한다. 기한 경과만으로 전부 수동 검수로 올리지 않는다.
- 현재 상품들이 과거 근거만 보유한 경우, 공식 발표 자동 승인은 다음 성공 수집부터 적용된다. 과거 데이터를 일괄 승격하지 않는다.
- 배포 전 시뮬레이션과 테스트를 수행한다. 운영 배포·실제 알림·전체 재수집은 별도 승인 후 실행한다.
- 롤백 시 기존 `decision` 공개 계약과 수동 판정 파일을 그대로 사용할 수 있다. 새 queue는 파생 데이터로 재생성 가능하다.
