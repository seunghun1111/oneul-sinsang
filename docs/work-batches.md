# 작업 묶음 운영

관련 수집기를 기능 단위로 함께 수정·검증하고, 중간 보고는 중요한 변경·위험·차단 사항에 한정한다. 완료 보고에는 적용 범위, 검증 결과, 배포 여부, 남은 제한을 한 번에 정리한다. 운영 배포는 사용자가 해당 작업에 승인한 경우 묶음의 마지막에 수행한다.

## 이번 묶음: 수집 안정성

- 편의점·외식·아이스크림·추가 치킨·커피의 전체/부분 실패 보고
- 기존 NEW 목록 또는 커피 경로가 갑자기 0건이면 기존 데이터 유지
- 정상적인 개별 NEW 교체는 계속 반영
- 실패·이상 상태의 반복 알림 억제 및 복구 후 재발 구분
- 전체 테스트, 타입 검사, 빌드 후 한 번에 배포

이 보호는 실제 NEW 전체 종료와 파서 오류를 자동 확정하지 않는다. 갑작스러운 전체 0건은 관리자 확인 대상으로 보수적으로 남긴다.

## 다음 후보 묶음: 운영 가시성

수집 결과 요약, 브랜드별 마지막 정상 확인 시각, 확인 필요 사유를 함께 볼 수 있도록 관리 화면을 개선한다. 새 외부 알림 채널이나 접근 권한 변경은 별도 승인 대상이다.

구현·검증 범위: 47개 브랜드 경로, 최근 수집 결과·실제 마지막 전체 성공 이력·이상 사유·36시간 갱신 지연, 그룹/브랜드/확인 필요 필터를 제공한다. 운영 현황 조회 실패는 상품 검수와 분리한다. 자세한 제한과 배포 순서는 collection-operations.md를 따른다. 운영 배포는 사용자 승인 후 GitHub 데이터·Sites 화면 순서로 진행한다.

## 다음 후보 묶음: 수집 품질

브랜드별 구조 검증, 검수 대기 근거 재확인, 페이지 누락·중복 식별을 함께 점검한다. 날짜·추천 표시만으로 NEW를 추정하거나 기존 수집 정책 제한을 완화하지 않는다.
